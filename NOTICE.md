# Attribution

Tier and effort rubrics, confidence/risk/ceiling rules, follow-up recognition, skill questions/gates/none policy, batching/shortlist/rerank rules, strategy/quality questions and advice gates, UI design question/probability gate/configured skill defaults/reference guidance, repeated-work observation and common step-back note, context minimization, platform markers, custom-slot name/count/default descriptions/mode eligibility, junior definition/mapping, crew advice, and the decision-ledger entry shape, 500-entry bound, correction marking, report summary, and the tuning proposal rules, ranges and apply/reset lifecycle are adapted from [Jev Pilot 0.12.1](https://github.com/Akramovic1/jev-pilot/tree/5d27135b34edf81b40c0bf1df01ae401f6b72ea7), commit `5d27135b34edf81b40c0bf1df01ae401f6b72ea7`, by Ahmed Akram, with portions by Daniel (San) Ávila. The upstream MIT notice is preserved in `LICENSE`.

This port targets official Pi, not Pi-Bolt. It implements effort selection, optional main-model tier routing through official virtual models, main-session skill matching through Pi resources and context projection, and strategy/quality/design advice through that same owned context seam. The design pack retains the project's design system as first priority and the upstream VoltAgent awesome-design-md reference URLs (linked guidance, not bundled third-party content). Configured resources come from Pi's public catalog; the Claude Skill tool is replaced with an exact resource-path read hint only when read is active. Mobbin/Inspo references name only exact active tools, without inferring schemas or invoking them. Strategy never dispatches workers or grants permissions; workflow guidance does not claim transparent interception. Loop observation uses public tool results without raising effort; the upstream Claude-specific Fable/high-effort tail is omitted. Pi's skill catalog remains intact; content injection uses Pi resource-directory conventions rather than Claude-specific file lookup or path substitutions. Claude family/substring ranking is replaced with exact configured physical identities; initial balanced is an approved host default adaptation. No upstream mid-turn escalation, worker engine, health probes, pet, or live controls are imported.

The optional `expert` tier above `deep`, its `expert_needed` question and strictly-above-0.9 admission gate are extensions of the pinned upstream design, not upstream behavior.
