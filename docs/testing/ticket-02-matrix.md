### Latest successful physical baseline (approved contract)

For fresh user routing, native `request.previous` (documented latest successful physical response in active request messages) takes precedence over saved Jev physical state. Use state only when previous is absent, then balanced when both are absent. Validate the chosen baseline, not an unused stale state identity. Manual physical selection is not a persistent lock: later eligible tier policy may still replace it. MAIN-13g verifies auto deep → manual fast successful turn → auto classifier failure retains fast, even if the old saved identity has disappeared; a fresh eligible decision may route again. MAIN-13h verifies an invalid selected previous fails actionably instead of masking it with saved state/balanced. MAIN-13i removes an unused old saved identity while keeping a valid latest physical baseline and current tier targets.

**Missing registry identity adaptation:** observed Pi 1.4.0 `model-runtime.js:742–749` omits `previous` when its latest successful assistant identity no longer resolves. When `previous` is absent, inspect public request messages for the latest successful assistant (exclude `error`/`aborted`); validate that exact identity before using saved state. Never skip an invalid latest successful identity in favor of older/state/default. This is a public transcript validation, not a private helper import. MAIN-13h covers removed identity; MAIN-13j missing auth; existing MAIN-07b excludes failed retry receipts; MAIN-26c covers compaction and MAIN-13c the fresh balanced default.

### Queued native user batch (approved after MAIN-26h RED)

A virtual `user` route runs once for the trailing batch of user messages after the last assistant/tool boundary. Use the last substantive user as anchor if followed only by plain continuation; do not reuse an older pre-batch decision in that case. Multiple substantive messages anchor the newest. A final approval remains an approval and is classified with bounded recent context. Only-continuation batches reuse valid branch-owned decisions; without one they classify normally. Tool continuation/retry never reclassifies. This is one decision per native batched model request, unlike the physical effort-only per-message hook. MAIN-26b/h/k/l/m/n/o assert anchor/count/physical dispatch, including tool and fork boundaries.

### Fresh user thinking input (approved contract)

Fresh `user` requests take `request.thinkingLevel` as effort baseline, with or without auto-effort. Native branch route state retains the physical target, not a second selected-thinking state. Plain user continuation reuses the decision but reapplies policy to current selected thinking. Fresh classifier failure keeps that new baseline. Only tool continuation/retry freezes the previously applied physical pair. This adapts upstream `route(decision, {model: e.model, effort: e.effort})` without equality-based provenance. MAIN-05d/e/f cover manual thinking between turns, enabled-to-disabled, and classifier failure against a new input.

### Native cancellation observation (approved before changing MAIN-26e expectation)

Actual Pi 1.4.0 CLI cancels a pending virtual route's request signal on manual model/thinking selection. The observed result is `agent_settled`, zero physical HTTP, and zero new route state, not fallback generation. Verify the manual selection survives and the next eligible prompt works (virtual routing or physical effort-only). This differs from the earlier physical `message_start` seam; do not treat selection cancellation as a classifier service failure.
