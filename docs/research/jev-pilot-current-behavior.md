## Key Code and architecture

### Lifecycle and prompt path

`plugin.json` declares a single module; `jev-pilot.ts` initializes feature defaults from options, initializes crew state, then registers model router → skill suggester → pet. Both decision modules hook `prompt.submit`; router is outermost. For an eligible user task, router reads recent context, prompt signals and project marker filenames, creates a pending part, and calls `next`. Skill suggester takes that part and combines router questions with skill/design questions. It settles the router decision from the same answer and attaches the router advice, skill block and optional design block to prompt context. If the skill module did not take the part, router withdraws it and makes its own fallback call. Handoff is keyed by prompt text because the event has no request ID, keeps per-text queues FIFO, and caps all waiting parts at 16. A plain continuation (`continue`, `go on`, etc.) reuses the last decision and skips a new classification; an approval such as `yes` is not treated as continuation. See [`jev-pilot.ts:19-39`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-pilot.ts#L19-L39), [`jev-model-router.ts:418-601`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-model-router.ts#L418-L601), [`jev-skill-suggestion.ts:271-339, 436-488`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-skill-suggestion.ts#L271-L339), and [`jev-call.ts:41-91`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-call.ts#L41-L91).

Router then waits for the main model's first `turn.step`, consumes the matching pending decision and applies model/effort only there. Subsequent requests in the same turn keep applied values except where the separate excluded mid-turn escalation/circle logic intervenes. `tool.call` observes tool outcomes and `turn.complete` closes the main turn ledger entry; subagent completion clears in-memory decisions and records usage stats. Events ignored as not the person's task include peer notifications, scheduled triggers, Slack pings, and typed `/commands`. Context keeps message text and tool names (with failed marker), not tool inputs/results; signals are counts/flags and avoid quoting the prompt. The main prompt itself is removed if already in transcript. [`context.ts:11-29, 38-99, 102-157`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/context.ts#L11-L29), [`jev-model-router.ts:628-867, 870-959`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-model-router.ts#L628-L867).

### System One API contract, provider/auth, probabilities and limits

`selectProvider` in `auto` order is TypeSafe → OpenRouter → Vercel AI Gateway → built-in classifier. Forcing a provider without that provider's key resolves to built-in; it does not borrow another provider's key. Defaults: TypeSafe `https://api.typesafe.ai/v1/systemone`, model `jev-latest`; OpenRouter `https://openrouter.ai/api/v1/systemone`, model `~typesafe/jev-latest`; Gateway `https://ai-gateway.vercel.sh/v4/ai/evaluation-model`, model `typesafe-ai/jev`. Requests use `Authorization: Bearer <provider key>`. TypeSafe/OpenRouter wire body `{ model, state, questions }`; OpenRouter is documented in source as TypeSafe-compatible. Gateway omits model from body, sends it in `ai-model-id`, and sets gateway auth/protocol/evaluation-specification headers. [`model-router.policy.ts:208-254, 372-419`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/model-router.policy.ts#L208-L254), [`jev-model-router.ts:207-226`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-model-router.ts#L207-L226).

Base typed decision questions include tier `choice`, effort `choice`, and risk as `noul` (TypeSafe/OpenRouter) or `boolean` (Gateway). Main-turn additions may include four quality `noul`/boolean questions and strategy choice; subagent prompt asks about execution effort but not recent context/strategy. Skill ranking uses `which` choice plus three request-level gate questions; gate's prose-suffices value is inverted before averaging. Design is a `noul`/boolean added to the first combined request. If rerank is enabled, separate `fits::<skill>` questions recheck shortlisted candidates. TypeSafe/OpenRouter answer nouls with a `noul` field and per-answer `confidence`; Gateway booleans use `probability`. Confidence parser uses reported confidence or max distribution value if available; missing distribution/confidence remains `null`. Effort named-choice distributions are mapped to ladder indices 0..4, weighted mean and distribution; old score responses are also accepted. [`model-router.policy.ts:322-369, 441-520`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/model-router.policy.ts#L322-L369), [`skill-suggestion.policy.ts:402-423, 475-550`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/skill-suggestion.policy.ts#L402-L423).

Default request latency budget is 1500ms. Both plugin modules use `Promise.race(fetch, sleep(timeout))`; timeout/non-2xx/malformed response is fail-open (no routing/suggestion). Busy statuses are distinguished for logs. Important limitation: this timeout race does not pass an AbortSignal to or abort the in-flight classification `fetch`; it limits hook waiting rather than proving backend work is cancelled. There is no live endpoint test in this research. [`jev-model-router.ts:132-163`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-model-router.ts#L132-L163), [`jev-skill-suggestion.ts:310-339`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-skill-suggestion.ts#L310-L339).

By default (with external backend, normal skill candidate roster, `rerank=false`), one skill-ranking request includes router questions, skill gate/ranking and design question. Larger catalogs split into balanced batches of at most 254 skills per batch (`MAX_CHOICES=255`, one choice slot reserved for `none`); first batch carries router questions/gate/design, later batches are separate parallel calls. With `rerank=true`, additional request(s) re-read top candidates and can reject all. If skills disabled/no candidates/module skipped, the router can send its own standalone decision request. Thus README's “one request per prompt” should be read as the typical unbatched, default-rerank-off path—not an absolute maximum. [`jev-skill-suggestion.ts:436-488, 496-523`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-skill-suggestion.ts#L436-L488), [`skill-suggestion.policy.ts:425-473`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/skill-suggestion.policy.ts#L425-L473), [`plugin.json:311-321`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/.claude-plugin/plugin.json#L311-L321).

### Decision vs actual agent spawning; custom-model proxy

Strategy outputs prompt-context instructions only. `adviseStrategy` returns a text block, explains it may be ignored, and contains no spawn invocation. Actual routing has separate execution seams: `agent.spawn` rewrites subagent model before passing to engine; Agent's own task/Claude action must still choose to spawn. `jev-pilot:junior` and reviewer agent types are registered through `$.agent.register`; the hook handles them specially if called, but does not create a task or spawn by itself. Workflow-created agents that bypass Agent tool are explicitly noted as unrouted and must set their own model. [`model-router.policy.ts:870-927`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/model-router.policy.ts#L870-L927), [`crew-run.ts:192-212`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/crew-run.ts#L192-L212), [`jev-model-router.ts:1020-1175`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-model-router.ts#L1020-L1175).

`claude-jev` turns on function hooks and may start the local proxy. It listens only on `127.0.0.1` (port 8799 by default); request URL includes 32-hex secret path in `~/.claude/jev-pilot/router-secret`, and requests with Origin or Sec-Fetch-Site are refused. `jev-<slot>` requests route to OpenRouter using the OpenRouter key; all other Claude traffic passes through with the session's Anthropic headers. Router filters Anthropic-only metadata/safeguards/context-management from custom-model requests, translates tool-search/announced tools, and on custom-model failure falls back to a learned Sonnet/Claude model when available. Client disconnect aborts upstream proxy work. This proxy's cancellation is separate from classifier timeout behavior above. ### Model pool construction and selection

The pool is configuration, not an automatically benchmarked leaderboard. Three configured mappings (`fast`, `balanced`, `deep`) default to Haiku/Sonnet/Opus. The actual tier question asks: "Which is the cheapest tier that can complete this coding task well?" Current tier criteria explicitly mention those Claude families: fast is read-only lookup; balanced is understanding-heavy read-only work or clear-spec, verifiable changes; deep is judgment, open specifications, unknown-cause bugs, long multi-component work, security/migrations/production/money. See `model-router.policy.ts:183-192,322-333` at the pinned commit.

Custom slots carry `name`, `model`, and a configurable `when` description. In budget/junior-lead routing, eligible slots replace the fast option in the classifier question, while balanced/deep remain. Slots do not form an independently ranked price/capability leaderboard; the question includes model ID and `when`, not measured per-task model accuracy. Main routing uses configured tier mappings; custom-slot selection described here is for subagents. Junior is a separate named-agent path using the configured junior slot (or first slot), not a fresh ranking among all slots. See `crew.ts:36-85,121-145,260-272` and `jev-model-router.ts:1058-1109`.

Port decisions still open: role rubric semantics beyond Claude families; separate main/worker mappings; model capability eligibility; custom-role descriptions. A Pi registry entry and credentials alone do not establish task suitability. Ledger observations do not establish counterfactual performance/cost for models that did not run.

### Policy and aliases

Model tier upgrade bar default `0.3`; downgrade `0.6`; effort upgrade/downgrade use their own confidence bars. Risk question concerns executing changes against production/moving real money/altering unrecoverable data; `risky > 0.7` forces deep tier and at least `high` effort, bypassing confidence thresholds, without lowering an already higher effort. Follow-up short non-question may raise but not lower effort. Main model change is feature-off by default; model alias family resolution retains exact current model when same tier. [`plugin.json:112-134`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/.claude-plugin/plugin.json#L112-L134), [`model-router.policy.ts:765-849`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/model-router.policy.ts#L765-L849), [`model-router.policy.ts:659-685`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/model-router.policy.ts#L659-L685).

Effort rubric is `low`, `medium`, `high`, `xhigh`, `max`; the close-call lean stops at `high`. Turn starts capped by `maxEffort=xhigh`; mid-turn max/step-up path is separate. Cache detection can hold effort after first turn on Bedrock, Vertex or non-Anthropic upstream; compaction releases it. These are adjacent runtime behaviors, not live-tested here. ### Crew behavior in requested modes

`standard` is default and offers no custom slots for Jev's subagent choice. `budget` exposes active custom slots as cheap-end options for subagent routing. `junior-lead` does the same and provides the separate named junior agent; strategy choice `junior` is included only if a usable junior slot exists, and its advice is suppressed for deep or risky work. Lead review/test behavior is conveyed through agent briefs and strategy advice, not established here as an engine-enforced review gate. The custom model is still reached only when the agent spawn is routed through the local proxy. Custom slots configured at plugin options support legacy alpha/beta/gamma as well as arbitrary `/jev <name> <model>` slots. `second-opinion` and `quality` external-review modes exist but are out of the selected scope; no external review behavior is claimed as validated here. ### Ledger, privacy, corrections and tuning lifecycle

The ledger is not an explicit filesystem path: hooks read/write plugin-host `$.store` key `ledger`; each entry holds timestamp, answered/latency, tier and confidence, effort score/confidence, start/raised effort, tool/failure counts, strategy/advised, outcome/duration/output tokens, optional turn ID and correction flag. It keeps latest 500 valid entries. Prompt content is not in the ledger entry type. This is distinct from data leaving the device: configured hosted decision backends receive current prompt text and bounded recent text context. Skill endpoint also receives skill names/descriptions and (depending on rerank path) skill excerpts. The source docs explicitly call out this disclosure. [`ledger.ts:11-80`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/ledger.ts#L11-L80), [`jev-model-router.ts:55-56`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-model-router.ts#L55-L56), [`jev-skill-suggestion.ts:70-72`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-skill-suggestion.ts#L70-L72).

At next eligible classified prompt, correction read threshold is `QUALITY_BARS.corrects=0.7`. The previous completed entry's exact engine turn ID is marked true/false, not matched by time; a positive correction also increments session stats. Main turn closure stores the ledger only when `recordDecisions` is enabled. `/jev-pilot:report` reads ledger store, summarizes it and reads `~/.claude/settings.json` only to find plugin config keys. If there are suggestions, it tells the model to show the report and offer—not perform—a settings Edit; explicit user consent is required. `/jev-pilot:report reset` deletes only ledger key. [`jev-model-router.ts:506-515, 925-959, 993-1018`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-model-router.ts#L506-L515), [`ledger.ts:48-67, 261-297`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/ledger.ts#L48-L67).

Tuning uses separate plugin store key `tuning`. It only considers entries newer than last applied change. Proposals need 20 turns; runtime `/jev tune apply` applies computed proposals immediately in this worker and stores them (over settings), while reset deletes learned values and restores settings defaults. `/jev tune reset` is not the same as `/jev-pilot:report reset`. Proposals considered: timeout if >10% of asked calls miss and successful-response p90 supports a higher timeout; downgrade confidence/margin up when >=20% of >=10 low/medium-start turns are raised or corrected; high-confidence bar up when >60% of >=10 `high` starts were short/clean; margin down when >60% of >=10 `xhigh/max` starts were short/clean and there is no contrary signal. Numeric values are clamped. [`ledger.ts:83-100, 121-196`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/ledger.ts#L83-L100), [`tuning.ts:17-107`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/tuning.ts#L17-L107), [`jev-pet.tsx:180-202`](https://github.com/Akramovic1/jev-pilot/blob/5d27135b34edf81b40c0bf1df01ae401f6b72ea7/hooks/jev-pet.tsx#L180-L202).

## Architecture

`claude-jev` launcher → Claude Code function hooks → single plugin entry → (main prompt) router offers pending typed-decision closure → skill module optionally consumes it and merges skill/design questions → policy reads one answer and adds context blocks → `turn.step` applies routing → `agent.spawn` routes non-fork subagents; optional custom slot alias flows through localhost proxy to OpenRouter → `tool.call` / `turn.complete` observe outcomes → plugin store ledger and tuning/report.

The decision model does not independently browse repository source code: inputs are the latest request, limited recent conversation, derived counts/platform filenames, and candidate skill metadata/excerpts. Code or secrets included in those text inputs may therefore reach the classifier; this research found no basis to claim automatic secret redaction. Strategy is advisory; the engine/model actually spawning remains responsible for taking that recommendation. Custom proxy model routing is the part that performs endpoint translation/fallback; it is not the System One decision endpoint.
