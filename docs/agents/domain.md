# Domain Docs

## Read Before Exploring

- Read root `GLOSSARY.md` when present.
- If `GLOSSARY-MAP.md` exists, follow it to relevant context glossaries.
- Read relevant ADRs under `docs/adr/`.

Proceed silently when these files do not exist. Create domain documents
lazily through domain modeling when terms or decisions are resolved.

## Layout

This project uses a single-context layout:
- `GLOSSARY.md`
- `docs/adr/`

## Vocabulary and Decisions

Use glossary terms in specs, tickets, tests, and explanations.
Surface conflicts with existing ADRs explicitly rather than overriding them.
